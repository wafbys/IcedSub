# 决策记录（DECISIONS / ADR）

> 本文件是项目的**唯一事实来源**（single source of truth）之一。
> 术语：**ADR = Architecture Decision Record（架构决策记录）**。
> 规则：
> - 每条决策都有 `状态`：`已定` / `暂定`（默认兜底，可推翻）/ `待议` / `已废弃`。
> - 推翻一条决策时**不要删除**，改为 `已废弃` 并注明被哪条取代。
> - 讨论中产生的矛盾先记到「矛盾与开放问题」，达成一致后再升级为决策。

最后更新：2026-10-08

## 一、现行决策（兜底默认，随时可推翻）

### D1 技术栈
- **状态**：暂定
- **决定**：留在 **.NET 10**，发布为 **单文件、自包含（single-file, self-contained）** CLI。**不从零重写**，在现有代码上重构。
- **理由**：已有可用代码、测试、发布配置；.NET 的单文件/自包含/AOT 成熟；System.CommandLine、异步 HTTP、正则、跨平台都够用；重写会丢掉已有的 ASSRT 容错、配置分层、发布链。
- **后果**：媒体探测/同步需依赖外部二进制（见 D2）。

### D2 外部依赖策略
- **状态**：暂定
- **决定**：**exe 保持单文件**；`ffprobe` / `ffmpeg` / `MediaInfo` 视为**可选外部工具**，通过 PATH / 环境变量 / 常见安装目录发现（复用 `rank_videos.py` 的 `find_tool` 思路）。
  - **缺了也要能跑**：降级为“无探测/无内嵌检测/无同步”，主流程（搜索+下载）不阻断。
- **理由**：单文件 exe 无法内置 ffmpeg；强行内置会破坏“便携 + 单一文件”，并带来体积与授权问题。
- **后果**：探测/同步类功能是“增强”，不是“必需”。

### D3 配置与密钥
- **状态**：暂定
- **决定**：
  - **配置**：便携旁置（**application-local / sidecar config**），即与 exe 同目录的 `appsettings.json`。
  - **密钥**（OpenSubtitles Key、ASSRT Token、TMDB Key）：**走环境变量**，不写进旁置配置文件。
  - **默认禁用** `%AppData%\IcedSub\` 这一层（可保留为显式开启的兼容选项）。
- **理由**：兼顾“便携”（配置随程序走）与“安全”（密钥不进会被备份/同步/误提交的文件）。
- **后果**：新机器需设置环境变量后才能用密钥类功能。

### D4 媒体库结构
- **状态**：暂定
- **决定**：
  - **电影/纪录片**：`<Library>/<规范目录名>/<发行版视频文件...>`
  - **剧集/综艺**：`<Library>/<规范目录名>/<SxxExx 视频文件...>`（**一剧一目录**，集数用文件名区分）
  - 规范目录名 = `name` 命令产物：`中文名_English_(年份)_imdb-ttid_douban-id`（细节见 D12 与 `SPEC.md`）。
  - **一个字幕文件对应一个视频文件**，命名为 `<视频名>.<lang>.srt`（播放器可自动挂载）。
- **后果**：目录名携带身份 → 字幕检索可直接用其中的 `tt` id。

### D5 身份主键
- **状态**：暂定
- **决定**：**IMDb id（`tt…`）为对外主键**，**TMDB id 为内部辅助**（取元数据/图/简介），二者都记录。
  - 解析入口：**优先从目录名**取 `tt`；其次文件名；最后 TMDB 反查。
  - **无 tt 兜底键**：`tmdb-<id>`；再不行用 `标题_年份`。
- **理由**：IMDb id 跨服务最通用、语言无关、稳定；OpenSubtitles 等源直接接受。
- **已知边界**：id 标识“作品”而非“版本”；冷门/地区内容可能无 tt；剧集 tt 指剧集而非单集。

### D6 字幕落盘命名
- **状态**：暂定
- **决定**：`<视频文件名不含扩展名>.<lang>.srt`（如 `Movie.2025.2160p.WEB-DL.zh-CN.srt`）。
  - 源站原名保留在内部元数据/日志，不用于落盘主名。
- **理由**：让播放器/媒体服务器能自动匹配字幕——这是当前实现最主要的“下了不认”问题。

### D7 下载目标
- **状态**：暂定
- **决定**：**默认只给“最优/KEEP 版本”下载一条**；`--all` 才给目录内每个视频下载。
- **理由**：默认全下会产生大量不匹配字幕，放大“时间轴不对”的体感。

### D8 内嵌字幕
- **状态**：暂定
- **决定**：探测到视频**内嵌首选语言字幕**时，**默认跳过下载**；`--force` 覆盖。
- **理由**：对应“资源常自带/内嵌字幕”的现实，避免画蛇添足。

### D9 时间轴同步
- **状态**：暂定
- **决定**：
  - **一期**：**帧率线性校正**（23.976/24/25/29.97 之间的平移缩放，纯计算）+ 时长比对告警。
  - **二期**：可选**音频级自动同步**，通过集成外部工具（alass / ffsubsync）实现，**不自研**。
- **理由**：一期成本低、覆盖最常见漂移；二期准确性最高但工程/依赖成本高。

### D10 rank_videos.py
- **状态**：暂定
- **决定**：**保持独立**，继续负责“目录内选发行版 + KEEP/DROP 标记”。
  - IcedSub **只复用其探测能力的一小部分**（duration / fps / resolution / 内嵌字幕轨），在 C# 里另建 `MediaProbe`。
  - **不整包移植**；如未来要单 exe 全包，再单独评估移植排序逻辑。
- **理由**：Python/ffprobe 栈与 .NET 单文件冲突；两者是“选片”与“配字幕”的不同阶段。

### D11 文档
- **状态**：已定
- **决定**：以 `docs/SPEC.md`（规格）与 `docs/DECISIONS.md`（本文件，决策）为唯一事实来源；其余文档（README 等）不得与二者冲突。

### D12 命名格式（目录名）
- **状态**：暂定（2026-10-08 由用户给出示例）
- **决定**：规范形式（半角、下划线分段）：
  ```
  中文名_English_(年份)_imdb-ttid_douban-id
  例：肖申克的救赎_The Shawshank Redemption_(1994)_imdb-tt0111161_douban-1292052
  ```
  - 分段用 `_`；**年份用半角括号**；id 带 **`imdb-` / `douban-` 前缀**。
  - **不含导演**（与旧格式不同；导演等以后放元数据/NFO）。
  - **无中文** → 省略中文段（`English_(年份)_…`）；中英相同 → 只留一段。
  - **豆瓣 id**：Wikidata `P345(IMDb) → P4529(豆瓣)` 自动查询；`--douban <id>` 手动覆盖；查不到则**整段省略**（不报错）。
  - 剧集同形式，年份取首播年，豆瓣取剧集 id（`tv` 分支待实现）。
  - **交互**：`name` 默认进入“填空”流程——输入 tt / 豆瓣 id（任填其一或都填）→ 程序反查其余字段 → 逐项回车确认或输入新值覆盖（`-` 清空）→ 确认后打印目录名。
  - `-y` / `--yes`（或输入被重定向）时跳过交互，直接输出，适合脚本。
- **理由**：中文在前便于检索；id 带前缀便于识别来源；豆瓣补齐中文世界的第二主键。
- **后果**：与旧格式（`English (中文)_year_Director…`）**不兼容**；README、帮助文本、测试已同步；豆瓣 id 依赖 Wikidata，覆盖不全时会缺段。

### D13 产品命名（IcedSub）
- **状态**：已定（2026-10-08 用户拍板）
- **决定**：产品名由 **IcedSubDL** 改为 **IcedSub**，同步更名：
  - 解决方案 `IcedSub.slnx`；项目 / 命名空间 `IcedSub.Cli|Core|Providers|Metadata|Tests`；exe / 程序集 `IcedSub.exe`。
  - 环境变量前缀 `ICEDSUB_`；用户配置目录 `%AppData%\IcedSub\`。
  - README、帮助文本、`run-debug.ps1` / `run-release.ps1` 同步。
- **理由**：`Iced` 为个人品牌前缀（与 `IcedPicViewer` / `IcedUserScript` 一致）；`SubDL` 只表达“下载”，而项目已扩展到搜索、命名、媒体库整理，且 `SubDL` 与既有 `subdl` 工具 / 站点撞名；`IcedSub` 更准且更短。
- **后果**：**env 前缀与配置目录为破坏性变更**——旧 `ICEDSUBDL_*` 环境变量与 `%AppData%\IcedSubDL\` 配置不再生效（当前无外部用户，影响可控）。仓库根目录已一并由 `IcedSubDL` 重命名为 `IcedSub`。

## 二、矛盾与开放问题（讨论后再升级为决策）

### C1 单文件 exe ↔ 需要 ffprobe/ffmpeg
- **现象**：要求“单一执行文件”，但探测、内嵌字幕检测、同步、合并 rank_videos 都要外部二进制。
- **我的建议**：**不矛盾**，用 D2 的“可选依赖 + 优雅降级”化解。主流程零外部依赖；增强功能有则用、无则退。
- **需你确认**：能否接受“没装 ffprobe 时，部分功能不可用”。

### C2 便携旁置配置 ↔ 密钥安全
- **现象**：配置放 exe 旁（便携）会把密钥暴露在会被备份/同步/误提交的位置。
- **我的建议**：D3——**配置旁置、密钥走环境变量**。若你坚持密钥也进文件，则用单独的 `secrets.local.json` 并 gitignore。
- **需你确认**：是否接受“新机器要手动设环境变量”。

### C3 “资源多自带/内嵌字幕” ↔ 仍做字幕下载
- **现象**：早前判断该功能价值区间窄；但库化后仍需为“缺中字”的发行版配字幕。
- **我的建议**：**不矛盾**。优先级是：**先内嵌检测（有则跳过，D8）**，再为缺字者下载。工具价值定位为“补齐没有中字的发行版”。
- **需你确认**：默认是否 `skip-if-embedded` 打开。

### C4 电影式“一目录一片” ↔ 剧集/综艺/纪录片
- **现象**：目录命名规则对电影成立；剧集必须一剧一目录（D4），且 `name` 目前**只支持电影**。
- **我的建议**：以 **TMDB 的 `media_type`** 决定目录模型；`name` 补 `tv/{id}` 分支（剧名 + 首播年，不含导演）。
- **需你确认**：剧集目录名是否也带 tt，以及是否保留“导演”段。

### C5 rank_videos “不信任文件名” ↔ 本工具重度依赖文件名
- **现象**：rank_videos 明确“评分从不使用文件名（声明不可核验）”；而 IcedSub 的匹配几乎全在文件名上。
- **我的建议**：统一原则——**身份来自目录 id，技术事实来自探测，文件名只做候选筛选/展示**。逐步降低对文件名字符串匹配的依赖。
- **需你确认**：是否接受这条总原则。

### C6 “人工决定目录名” ↔ 自动化入库
- **现象**：`name` 现在只打印，不做落盘/建目录，无法批量。
- **我的建议**：`name` 增加 `--print`（只输出名字，供脚本/重命名）与 `--mkdir`（直接创建规范目录）；默认仍只打印。
- **需你确认**：是否需要 `--mkdir`。

### C7 目录名 vs 媒体服务器规范
- **现象**：`English (中文)_year_Director (导演中文)_ttid` 不是 Emby/Jellyfin/Plex 的标准命名。
- **我的建议**：若未来要喂媒体服务器，目录名收敛为 `Title (Year) [tt…]`；导演等信息放 NFO/元数据。**现在先不动**，但记入待议。
- **需你确认**：这个库是否只做本地使用。

### Dnn 标题
- **状态**：待议 | 暂定 | 已定 | 已废弃（被 Dxx 取代）
